# RC1 外部文档挑战评测

2026-09-08 对尚未用于此前调参的 FastAPI 中文资料执行 24 题、3 种检索方法，共 72 次正式问答。全部完成且无执行错误，但三种方法的严格通过均为 **13/24**。本轮证据不足以支持发布正式版；优先问题是资料不足时的拒答、无依据补答和逐项引用的语义对应。

这是 AI 在首次运行前拟题、固定标准，并由 AI 逐条复核的外部挑战。它独立于原有运维开发题，但不是独立人工标注或真实用户评测，也不能证明资料未进入模型预训练。

## 逐题语义复核

三项指标分别回答：正文是否直接回应且无错误事实、是否覆盖全部必要事实、每条结论是否由它自己的引文支持。允许同义表达和明确的语义蕴含，不要求关键词逐字出现；引文中有而答案正文没说，不能直接算正文完整。

## 代表性失败

| 题目与方法 | 实际结果 | 定位 |
|---|---|---|
| FN02，三种方法 | 将构建输出 `100%` 回答成镜像大小 `100 MB` | 有相关引文，但单位和事实含义不一致 |
| FN05，BM25 | 回答每个 worker 最多同时处理 1 个请求 | 将每容器一个进程误当成进程并发上限 |
| FN03，hybrid | 给出操作系统环境变量与 `.env` 的优先级 | 该知识未出现在冻结语料，也不由所引段落支持 |
| FN01，BM25；FN06，三种方法 | 正文说明资料未提供具体值，仍返回 `answered` 和 claims | 正文拒答与结构化状态不一致 |
| FA15，dense | 说 worker 对重启没有直接改善 | 与引文中对重启有一点帮助矛盾 |
| FA18，三种方法 | 核心答案完整，附加结论引用了不支持它的段落 | 逐字引用有效，逐项语义对应失败 |

用 FN02 的真实结果再次调用 `Service.validate_claims`，三种方法都能通过现有检查。原因可以从代码直接确认：当前检查来源 ID、引文是否逐字存在、字段和长度；它没有核验结论中的量值、单位或关系是否由该引文推出。来源编号机制保障原文位置可追溯，不能充当语义验证器。

## 修复顺序

1. 先处理可答性判定与输出状态的一致性。用完整负例和正例检查误答、状态不一致及误拒答；不能通过匹配几个拒答词语把 `answered` 强制改成拒答。
2. 验证逐项结论与其引用之间的支持关系，特别是数值单位、条件、异常类型和无关扩展。可以试验显式证据核对步骤，但同一小模型自检不等于已证明可靠，必须测代价与退化。
3. 约束重复和无关展开，并补齐多事实题必要条件。只有定位到召回缺口时再调整检索；本轮 Hit@4 已全部命中，单靠增加 top-k 无法解决上述错误。
4. 在原开发集与本题集上做回归，再新增另一组未看过结果的问题。修改开始后，本题集将成为回归集，修复后的分数不能继续宣称独立测试成绩。

本轮交付的是完整外部基线、问题定位和可复跑工具，未把这些质量问题包装成已修复。RC1 继续用于本地演示与开发，正式版本留待上述问题得到验证。
