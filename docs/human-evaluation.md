# 人工小样本评测协议

状态：2026-09-09首轮用户问题与人工评分已收到，已进行有界工程修复及开发回归。人工8题严格整题通过仍为0/8；同题修复后AI复核为1/8，未获人工复评分。当前不满足算法复现用途的质量门槛，详见[RC2结果](rc2-evaluation.md)。

## 首轮记录

首轮输入为一份包含公式、表格及跨页说明的英文技术文档，以及用户提供的8个中文问题。预先选定的8条hybrid输出中，3条返回正文、4条拒答、1条发生结构化输出校验错误；返回正文数不代表通过题数。人工依据技术正确性、必答点完整性和每条结论的引用支持，判定0/8完整通过；其中2题部分正确，1题拒答边界恰当但未完成任务，工程错误单列。

无正文题的技术正确性和引用支持保留为无法判断，不记成已证实的技术错误；部分正确和部分支持不计整题通过。无依据补充不等于认定有意捏造。用户未核验的文件结构信息也没有计为人工确认。

AI在首次调用前核对原文、整理参考事实并冻结输入；用户在看到首轮答案后确认主要参考依据并评分，因此不是运行前已获人工批准的金标。原始问题、逐题意见、论文副本和全部请求响应保留在本机忽略目录。这里的人工评分来自本会话用户，不声称独立第三方审核。修复后的同题运行将标为开发回归，保留本轮0/8的历史结果。

## 目标与来源

验证当前本地单人RAG在新资料和人工问题上的实际可用性。第一轮主对象为默认hybrid检索和当前本地模型组合。优先收集一份真实会查阅的技术文档及5至8个自然问题，不用AI补题凑样本数。小样本用来发现问题，不作为总体准确率估计。

必须分别记录问题提出者、必要事实标注者和最终评分者。人工提出问题、AI协助定位原文、人工核对标注并评分，可以称为人工出题与人工复核的小样本评测；不得称为无AI参与的标注。项目所有者本人评分不等于外部用户试用或独立第三方评价。

原FastAPI挑战、历史运维题和合成迁移样例均已用于开发，不能重新命名为独立人工题集。人工只给AI拟题打分时，需明确标为AI拟题、人工评分。独立在这里仅指新输入在本轮首次运行前未用于修改生成策略或选择结果，不保证文档未出现在预训练中。

人工输入和评分原件默认保留在被Git忽略的本机evidence目录；不因准备公开版本而自动公开私人文档、问题、身份或评价。

## 运行前冻结

1. 保存文档原始字节及来源路径或URL、取得日期、授权或公开许可信息。网页转换需同时保留转换说明；缺少的链接目标和图片不算模型可用证据。
2. 按人工原话保存问题，不为了迎合检索器而改写。记录是否看过系统回答、是否参考AI拟题，以及提出者与项目的关系。
3. 在看本轮答案前核对每题的直接需求、必要条件、可答性和支持原文。AI可协助找原文，人工需确认语义范围；不把题目没问的补充背景加入必答条件。
4. 为混合可答与不可答子问题保留各自的可答性。当前整问拒答协议与用户期望的部分回答分别记录，不能用协议通过掩盖未提供已知信息。
5. 冻结题目、文档、评分规则、代码与模型标识的哈希和时间。人工输入未到齐或参考事实未核对时，状态保持待补充，不填写虚构作者、答案或分数。

## 首次运行

复用现有 `scripts/import_eval_dataset.py` 和 `scripts/run_baseline.py`，在新目录导入、索引、运行和保存完整请求响应，不修改当前使用中的知识库。参考答案和评分标准不发给生成模型。

runner默认记录三种检索方法，也可通过--methods预先选择方法；第一轮人工主评分只针对预先确定的hybrid输出，其他方法作为诊断材料，未经人工评分不得并入人工指标。预热与正式记录分开，正式每题每方法一次，保留错误和拒答，不挑选重跑中的最好答案。

索引和批量运行均有落盘日志及逐请求状态；单个模型请求超时120秒，批次预算在启动时明确。只有真实运行完成后才生成待评答案包。

## 人工评分

评分包逐题提供问题、已确认的必要事实、系统正文、每条正文自己的引用和完整来源。先评答案，再展示检索方法、模型判断和自动指标，减少这些信息对评分的影响。AI整理评分包与汇总可以自动执行，人工评分字段保持空白直到收到真实人工判断。

| 维度 | 判定依据 |
|---|---|
| 正确性 | 直接回应问题，且没有错误事实、对象或单位混淆、无依据的因果强化。 |
| 完整性 | 正文覆盖运行前确认的直接需求和必要条件；同义表达允许，补充背景不强求。 |
| 引用支持 | 每一项结论由它自己的引文支持；引用逐字存在与语义支持分开。 |
| 拒答 | 整体不可答时不编造答案；可答却拒答按误拒答记录，区分检索遗漏与生成误判。 |
| 用户用途 | 能否解决提出者原本的问题，以及还需要补查什么；作为定性反馈单列。 |

每项取通过、不通过或无法判断，附具体理由和对应原文。无法判断的项目保持未决，不能由AI补成通过。混合可答题分别记录当前协议是否满足及用户需求是否满足，不混入完全可答题的完整性分母。

严格通过要求完全可答题的正确性、完整性、引用支持同时通过且实际输出答案；整体不可答题要求资料确实不足并返回无答案状态及空正文。运行错误和未完成评分保留在总数内。分别报告题数、已评分数、通过数、失败数和未决数；没有某类题时，该类比率标为不适用。

## 失败修复与发布衔接

先定位输入解析、检索证据覆盖、生成判断、正文完整性、引用对应或评分歧义，再修改对应环节。评分歧义先记录原标准下结果与人工意见，不事后悄悄改题提分。未观察到新的可复现问题时，不为完成阶段而强行改应用。

修复后原人工题集成为开发回归集；保留首轮结果，新增运行目录，不能将回归分数继续称为独立测试。需要确认是否能处理新问题时，再收集新的人工问题并重复冻结过程。

完成必要修复与回归后，准备新的候选安装包并执行干净安装、核心浏览器流程和发布文件校验。RC1附件不覆盖；仍有限制时继续标为预发布，并公开已知限制。随后整理简历和面试材料，区分AI辅助实现、本人掌握与实测证据，避免把离线题集写成真实业务准确率。
