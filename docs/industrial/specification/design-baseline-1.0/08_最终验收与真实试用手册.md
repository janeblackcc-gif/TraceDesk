# TraceDesk 最终验收与真实试用手册

## 1. 验收原则

- 从全新目录/卷/数据库开始；不使用开发者已有 data 目录。
- 每次 run 生成 `acceptance/<run-id>/`，含环境、镜像 digest、schema、模型 digest、命令、JSON、日志、截图、hash。
- 每个门槛只有 PASS/FAIL/SKIPPED-BLOCKED；“大致正常”不算。
- 工程验收和质量/真实试用分开。工程全 PASS 仍不能宣布产品完成。
- 失败 run 永久保留；修复后新建 run-id，不覆盖。

## 2. 环境记录

`00_environment.json` 必须包含：OS/kernel、CPU/RAM、GPU/VRAM/driver、Docker/Compose、Python、app image digest、PostgreSQL/pgvector、Ollama、model tag/digest、磁盘、时区、commit/tag、配置 hash（不含 secrets）。

## 3. 验收顺序与门槛

### FA-01 全新部署与 Schema
**映射**：PC-19；T-010,T-072,T-074。  
步骤：空 volumes → Compose up DB → `alembic upgrade head` → web/worker → `/livez,/readyz`。  
通过：schema=head；ready=true；无默认密码；重复 migration no-op。  
失败：应用在旧 schema 上仍接受流量、migration 报错但被忽略。

### FA-02 Bootstrap / 登录 / Session
**映射**：PC-01；T-020,T-021。  
输入：一次性 bootstrap token、admin 邮箱、强密码。  
通过：首 admin 创建；第二次 bootstrap 失败；Cookie Secure/HttpOnly/SameSite；logout 后 session 失效；日志无 token/password。

### FA-03 权限矩阵
**映射**：PC-02, PC-03；T-022。  
准备：admin/editor/viewer/无成员各1。  
动作：library、query、source、trace、export、upload、delete、index、member management。  
通过：矩阵与01一致；viewer 上传 403 且无 DB/file 变化；猜其他 KB source 不泄露元数据。任何越权读取=阻断 FAIL。

### FA-04 上传幂等与原文件
**映射**：PC-04；T-012,T-031。  
输入：`deploy.md` 两次相同 bytes。  
通过：同 revision/object；chunk 不增加；object sha256=输入；用户文件名不成为存储路径。

### FA-05 替换不中断旧版本
**映射**：PC-05；T-031,T-043。  
输入：v1 含“端口8088”，v2 改“端口8099”。  
步骤：v1 active → 上传 v2 → 在 parse/index 未完成时 query → 完成后 query。  
通过：构建中仍返回 v1；切换后只返回 v2；不存在半索引。

### FA-06 陈旧任务竞争
**映射**：PC-06/07；T-042。  
用 barrier/fake embed 让 v1 index 卡住，随后上传 v2 或删除文档，再放开 v1。  
通过：v1 job=superseded/cancelled，不能 active；删除后查询不可见。任何 stale write=阻断 FAIL。

### FA-07 删除生命周期
**映射**：PC-07；T-032。  
通过：删除事务后 query/source 立即不可见；软删除窗口可 admin restore；GC 后原对象在无引用时删除；legacy resolver 410；审计仍在。

### FA-08 模型 Digest 与索引
**映射**：PC-08；T-041。  
模拟同 tag 不同 digest/维度。  
通过：旧 generation 不误用；UI/API 标 expired/reindex required；维度不符拒绝写。

### FA-09 解析隔离
**映射**：PC-09；T-034。  
输入：正常 PDF、加密 PDF、空文本 PDF、hang fixture、内存压力 fixture。  
通过：异常 job 有稳定 error；hang 超时后子进程被 reap、temp 清空；同时 health/query 正常。Web 进程退出=阻断 FAIL。

### FA-10 Worker 崩溃恢复
**映射**：PC-10；T-025。  
运行 parse/index 中 kill -9 worker。  
通过：lease 到期后任务重领；attempt+1；最终副作用一次；无永久 running。

### FA-11 取消与队列
**映射**：PC-11；T-026。  
queued/running 各取消；填满 query queue。  
通过：终态正确；running 不在取消后激活 generation；queue full 429 + Retry-After。

### FA-12 在途撤权
**映射**：PC-12；T-023,T-052。  
slow model 开始后撤销 viewer。  
通过：最终请求不返回 claims/source/trace/export；后续 job/result 不可读。任何正文泄露=阻断 FAIL。

### FA-13 模型故障
**映射**：PC-13；T-044,T-052。  
停止 Ollama、返回 malformed JSON、超时。  
通过：RAG 明确 503/failed/partial 契约；evidence 模式仍可用；不请求云端未知地址；任务可取消/重试有预算。

### FA-14 SQLite 迁移
**映射**：PC-15；T-013,T-014。  
使用当前 RC2 demo/构造 DB。  
通过：dry-run 不改源；正式迁移 counts/hash/legacy id 对齐；重复执行 no-op；中断可续；旧 source 可解析。

### FA-15 备份恢复
**映射**：PC-14；T-073。  
构造 users/ACL/文档替换/软删除/active index/query → backup → 删除运行环境 → 新卷 restore。  
通过：hash、ACL、active、legacy、10题 smoke 一致；软删除不复活；恢复 RTO/RPO 有实测。

### FA-16 升级与回滚
**映射**：PC-19；T-074。  
执行一个真实 schema/app 升级；分别注入 migration fail 与新 app fail。  
通过：失败版本不接流量；按 runbook 恢复；不可逆变更不尝试危险 downgrade。

### FA-17 日志与审计
**映射**：PC-18；T-070,T-071。  
通过：敏感动作均有 audit；普通日志无 password/token/session/question/quote/DB URL；request_id 可串起 web/job；audit 读取有权限。

### FA-18 容量与混合负载
**映射**：PC-17；T-075。  
固定 50k chunk、20 用户、5 query 并发；混合 parse/index/query，至少30min。  
通过默认：非模型 API P95≤500ms；evidence P95≤2s；queue P95≤2s；RAG total P95≤30s；无 OOM、无无界队列、错误率在批准范围。若 M0/M8 冻结了新目标，以新目标为准并保留变更 ADR。

### FA-19 质量 Holdout
**映射**：PC-16；T-064。  
通过：使用封存 dataset hash；报告分子分母/CI；达到 M6 事先冻结阈值；权限/版本越界=0；所有失败保留。未达标阻断真实试点。

### FA-20 浏览器端到端
**映射**：PC-02/05/09/11；T-053。  
Edge/Chrome：登录、library、上传、job、query、source、replace、delete、cancel、export、390px、键盘。  
通过：无 JS/network error；权限/任务状态可见；source exact quote 定位；删除后无 stale UI。

## 4. 样例输入

建议验收 fixture：
- `deploy_v1.md`：默认端口 8088、备份间隔 7h；
- `deploy_v2.md`：端口 8099、备份间隔 13h；
- `error_codes.md`：E42/E43 不同前置条件；
- `no_answer.md`：与问题主题接近但不含答案；
- `encrypted.pdf`、`empty_text.pdf`、`parser_hang.fixture`；
- 两个 KB 中放相似内容用于越权/范围测试。

fixture 必须是原创/可公开测试材料，不能混入真实私密文档。

## 6. 失败判定

以下任一项直接阻止试点：
- 权限/版本越界；
- 删除/替换后陈旧任务写回；
- parser 可拖死 Web 或无法终止；
- 迁移/恢复数据不一致；
- backup 未成功恢复；
- holdout 严重错误/门槛未达；
- 容量出现 OOM、数据损坏、队列无界；
- secrets/原文进入普通日志；
- 模型失败静默切到未批准 provider。

可在试点前接受但需 ticket 的非阻断项：视觉小瑕疵、低严重度文案、非目标浏览器差异，前提是没有安全/数据/任务质量影响。

## 7. 工程通过后仍必须做的真实试用

**映射**：PC-20；T-081。

### 试用前置
FA-01~20 中适用工程/质量项 PASS；真实资料授权；真实用户同意；数据 owner 确认保留策略。

### 试用任务
每名用户至少覆盖：
1. 新人找到启动/环境配置；
2. 错误码/故障排查；
3. 版本冲突；
4. 无答案正确拒答；
5. 点击来源核验；
6. 维护人更新或删除资料（维护人角色）。

### 记录
- 是否完成任务；
- 是否找对版本；
- 是否需要维护人介入；
- 从提问到确认来源的耗时；
- 错误严重度；
- 是否重复使用；
- 用户自由反馈只作辅证，不替代任务结果。

建议 5–10 名目标用户、至少 7 天；如果实际用户更少，报告真实人数，不伪造样本。时间本身不等于覆盖。

## 8. 真实试用 PASS

在试点开始前由负责人冻结阈值。默认候选：
- 无权限/版本越界；
- 无高严重度错误导致用户执行错误配置；
- 任务完成率≥80%（小样本必须同时报分子分母）；
- ≥80% 任务能在不询问维护人的情况下找到可核验证据；
- 所有严重失败有复盘并决定修复/缩范围。

未满足则产品仍处于 pilot，不得用“RC/正式版”命名暗示工业化完成。

## 9. 最终签字

最终交付签字需要四方/角色（可由同一小团队不同职责承担）：
- 工程负责人：FA 工程门禁；
- 质量负责人：holdout；
- 数据/安全负责人：授权、ACL、备份/保留；
- 试点负责人：真实用户记录。

签字不是形式替代；每项必须引用具体 run-id 与 artifact。
