# TraceDesk 产品范围与验收契约

## 1. 产品定位与首批用户

首批产品定位：**实验室/小研发团队内部的版本感知技术文档证据工作台**。核心任务是新人交接、环境配置、部署步骤、错误码和已记录故障排查。系统帮助用户找到正确版本的证据并核验，不自动执行命令；复杂论文复现保留为挑战场景，不作为首批主任务。

默认用户：
- 新加入项目的学生/工程师：查询、查看来源、导出；
- 项目维护人：上传、替换、删除、重解析、重建索引；
- 工作区管理员：成员、权限、数据保留与审计；
- 评测维护者：冻结数据集、运行质量评测。

默认 5–20 注册用户、1 个工作区、5–30 个知识库；真实规模未确认。

## 2. 数据、更新和生命周期

默认支持 MD、UTF-8 TXT、文本型 PDF。首批保护值：单文件 20 MiB、PDF 200 页、解析后 2,000,000 字符；这些是可配置产品上限，不是解析器能力宣称。当前 RC2 的 10 MiB/100 页已验证，放宽必须依赖 M3 的进程隔离和 M8 压测。

原文件必须保留在 Web root 之外，以内容 SHA-256 对象名存储；用户文件名只作为元数据。解析产物不可覆盖原文件。

同一知识库内“逻辑文档”稳定存在；内容变化创建不可变 `document_revision`。更新流程：

`上传 → 原文件落盘 → parse job → parsed → index job → index generation ready → 原子切换 active revision/index`

任一步失败时旧 active revision 继续服务。相同 SHA-256 重复上传返回已有 revision，不重复建索引。

删除默认立即从查询面撤销、取消相关在途任务，并进入 7 天软删除窗口；物理清理后删除原文件对象、解析产物、chunk 和 embedding。备份副本按备份保留期另行处理，UI 必须说明“删除不等于立即从所有备份介质擦除”。

OCR 默认关闭。只有真实资料审计显示扫描件/图片 PDF 占比足以阻断任务，并获得额外资源与许可后，才进入 OCR 任务。

## 3. 权限角色

| 能力 | System Admin | Workspace Admin | KB Editor | KB Viewer |
|---|---:|---:|---:|---:|
| 登录、本人会话 | ✓ | ✓ | ✓ | ✓ |
| 查询、来源、本人导出 | ✓ | ✓ | ✓ | ✓ |
| 查看可见 KB 任务状态 | ✓ | ✓ | ✓ | ✓ |
| 上传/替换/删除 | ✓ | ✓ | ✓ | ✗ |
| 重解析/建索引 | ✓ | ✓ | ✓ | ✗ |
| 管理 KB 成员 | ✓ | ✓ | ✗ | ✗ |
| 查看安全审计 | ✓ | ✓ | ✗ | ✗ |
| 全局用户/系统配置 | ✓ | ✗ | ✗ | ✗ |

服务端默认拒绝。权限不是前端隐藏按钮；检索候选、来源正文、trace、导出、任务结果和评测数据都必须重新鉴权。权限撤销后新请求立即失败；在途查询在生成前、返回前各做一次授权版本检查，撤权后结果不返回正文。

## 4. 部署边界、硬件与成本

### 开发验证环境
保留当前 Windows 11、Python 3.13、RTX 4060 Ti 8GB、Ollama 0.33.3、Qwen embedding 0.6B + Qwen 4B 作为已测起点。它不承担多人容量承诺。

### 默认建议部署环境
- Linux x86_64，Docker Engine + Compose；
- 8 vCPU、32 GB RAM、≥200 GB SSD；
- PostgreSQL 18.6 + pgvector 0.8.6；
- API 1–2 进程；parse/index worker 分离；
- GPU：至少 8 GB VRAM 可继续跑当前 4B；若并发生成或更强模型需要额外 GPU，按 M6/M8 实测采购；
- 数据库和原文件必须在持久卷；模型权重可单独磁盘。

成本原则：先单机模块化部署。只有实测证明 GPU、数据库、存储或 HA 成为瓶颈，才拆机/托管。文档不虚构云费用；正式预算在 M8 前由实际供应商报价冻结。

## 5. 规模、并发和延迟目标

以下是**默认试点目标，不是当前成绩**：

- 活跃 chunk：50,000；单 KB 20,000；
- 原文件：20 GB；
- 同时登录用户：20；
- 查询并发：5；同时生成：默认 1（8GB GPU），有更大 GPU 时再提高；
- parse worker：2；index worker：1；生成队列最大 20；
- 查询排队 P95 ≤ 2 s（不含模型生成）；队列超过上限返回 429；
- 证据模式端到端 P95 ≤ 2 s；
- 本地 RAG：排队后首个“已开始生成”状态 ≤ 5 s；非流式兼容路径总响应 P95 目标 ≤ 30 s；实现流式后另测 TTFT，不能从总时长推算；
- API 非模型操作 P95 ≤ 500 ms；
- 月度可用性试点目标 99.0%，排除计划维护；正式 SLO 需按部署方式重定。

依据：当前顺序模型生成中位数约数秒、P95 可到十余秒，但没有并发容量数据，因此给 30 s 作为试点工程预算而非宣称已达。所有 SLO 以 M8 固定硬件和混合负载实测为准。

## 6. 支持平台与非目标

首批正式支持：桌面 Chrome/Edge 当前稳定版；Windows 11 客户端访问 Linux 服务。Firefox 作为兼容检查。Safari、移动触控、读屏认证在有用户需求时进入后续门禁。

首批非目标：
- 自动执行 shell/部署/修复命令；
- 公网匿名问答、跨组织 SaaS、多租户计费；
- 自动跨版本合并；
- 通用论文复现、复杂数学公式保证、复杂表格/图像理解；
- “引用存在即事实正确”；
- 高可用多机、Kubernetes、微服务；
- 无条件云模型回退。

## 7. 可观察验收场景

| ID | 场景 | 通过条件 | 关联任务 |
|---|---|---|---|
| PC-01 | 首次管理员初始化 | 只有一次性 bootstrap token 可创建首个管理员；token 用后失效 | T-020 |
| PC-02 | Viewer 越权上传 | 返回 403，数据库/文件系统无变化，审计有拒绝事件 | T-022,T-071 |
| PC-03 | 跨 KB 直接猜 source ID | 404/403 且不泄露文件名/页数 | T-022,T-050 |
| PC-04 | 同字节重复上传 | 返回原 revision，原文件对象和 chunk 数不增加 | T-031 |
| PC-05 | 替换文档 | 新 revision 完整 ready 前旧版继续查询；切换后旧内容不再命中 | T-031,T-043 |
| PC-06 | 替换时旧索引任务晚返回 | 任务标记 superseded，不得写入 active generation | T-042,T-043 |
| PC-07 | 删除时仍有索引任务 | 删除 tombstone 后旧任务提交 CAS 失败；查询立即不可见 | T-032,T-042 |
| PC-08 | 模型 digest 变化 | 旧 embedding generation 保留但不可作为新模型 ready；提示重建 | T-041 |
| PC-09 | 解析超时 | 子进程被终止，临时目录回收，job=failed(timeout)，Web 仍可服务 | T-034 |
| PC-10 | worker 崩溃 | lease 过期后任务可重领；attempt 增加但不重复提交副作用 | T-025 |
| PC-11 | 用户取消 | queued 立即 cancelled；running cooperative cancel；最终提交前再检查 | T-026 |
| PC-12 | 权限撤销中的查询 | 返回前权限版本变化则 403/409，不返回来源、trace 或导出内容 | T-023,T-052 |
| PC-13 | 模型离线 | 查询得到明确 dependency error；证据模式仍可用；不静默转云 | T-044,T-052 |
| PC-14 | 备份恢复 | 恢复后用户/ACL、原文件 hash、active revision、关键查询一致 | T-073 |
| PC-15 | SQLite 旧数据迁移 | dry-run 数量/hash 对齐；迁移可重复；旧 ID 可解析 | T-013,T-014 |
| PC-16 | 质量留出 | 冻结 holdout 只运行一次正式放行；失败逐题保留 | T-061,T-064 |
| PC-17 | 混合负载 | 在冻结规模下达到 SLO，队列/内存/VRAM 无失控增长 | T-075 |
| PC-18 | 审计 | 上传、删除、权限变更、导出、登录失败可按 request_id/user/resource 检索 | T-071 |
| PC-19 | 升级失败 | 数据库迁移失败时应用不启动新版本；按 runbook 恢复旧版本 | T-074 |
| PC-20 | 真实试用 | 真实用户完成规定任务并保留失败、核验耗时与是否需维护人介入 | T-081 |

## 8. 质量门槛的冻结方式

旧文档中的 0.85/0.90 等数字只能作为候选。M6 在看到真实任务风险、样本量和标注一致性后冻结正式门槛。默认建议用于**试点**而非正式 SLA：

- 权限/版本越界：0；
- 严格任务通过率：≥85%；
- 逐条 claim 有人工确认支持的比例：≥95%；
- 困难无答案拒答召回：≥90%；
- 可答题误拒答：≤10%；
- 关键“执行步骤/配置值”类题不得出现高严重度无依据新增。

若样本不足，必须报告置信区间/原始分子分母，不能只报百分比。
