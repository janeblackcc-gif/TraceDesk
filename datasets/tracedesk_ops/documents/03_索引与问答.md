# TraceDesk 索引、问答与引用

本文描述当前真实代码中的索引与回答流程。

## 建立向量索引

本地 RAG 的混合检索需要先为所选知识库和版本建立向量索引。
系统通过嵌入模型的标签和 digest 标识索引；模型 digest 改变后，旧索引不能用于新的模型标识，需要重新建立索引。
建立索引时只计算当前模型标识下缺失的分块向量，每批最多处理 8 个分块。

## 查询范围与候选

程序先按知识库、版本和可检索状态限定文档范围，再执行检索。
混合检索结合 BM25 关键词匹配和嵌入向量相似度，并融合两路排名。
检索结果最多返回 5 个候选片段，生成模型只接收其中排名前 4 个片段。

## 证据不足

没有检索到足够相关的片段时，返回 no_evidence 状态。
检索到片段后，生成模型仍可以判断所问事实缺少依据并拒答，此时也返回 no_evidence 状态。
候选片段与主题相关，不代表片段中一定包含答案。

## 引用校验

每条生成结论必须引用本轮提供给模型的片段，引用原文必须是对应片段中的连续文本，长度为 8 至 600 个字符。
逐字引用校验只能确认引用位置和原文匹配，不能证明结论在语义上正确或完整。
引用校验失败时，系统明确降级为原文摘录，并显示警告。

## 输出与服务异常

模型输出达到长度上限时，系统报错，不接受可能不完整的答案。
模型服务不可用、请求超时或返回无法解析的 JSON 时，接口返回 HTTP 503。
本地单人服务正在执行另一项受锁保护的操作时，新请求可能返回 HTTP 409，表示当前忙碌。
